# Agent Instructions

## Cursor Cloud specific instructions

Follow the always-applied [.cursor/rules/gitleaks.mdc](.cursor/rules/gitleaks.mdc) before changing, committing, or opening/updating a PR. Before any commit, if `gitleaks version` or `semgrep --version` fails, run `bash .cursor/install-security.sh` (and `git config core.hooksPath .githooks`), then re-run the scan. Cloud setup runs `bash .cursor/install-security.sh` via `.cursor/environment.json` to install checksum-verified Gitleaks and pinned Semgrep, enable `.githooks`, and run the production audit/code gates. In each fresh shell, run `export PATH="$HOME/.local/bin:$PATH"` for the fallback install directory, then stage changes and run `.githooks/pre-commit`. Use the GitHub noreply identity and keep secrets and personal data out of code, prompts, and PR text.

## Dependency and Code Security Gates

Before any commit, if `gitleaks version` or `semgrep --version` fails, run `bash .cursor/install-security.sh` (and `git config core.hooksPath .githooks`), then re-run the scan. The shared `.githooks/pre-commit` hook applies to Codex and Claude Code on the Mini and to Cursor agents. It retains Gitleaks, audits staged production package metadata when package files change, and scans the staged source bytes with the offline rules in `.security/semgrep.yml`. Enable `git config core.hooksPath .githooks`; never bypass a failed gate. Run `python3 .security/scan.py all` before opening or updating a PR and before publish, alongside the existing privacy/package checks. Findings, narrowly pinned exceptions, expiration dates, coverage and remediation follow-up are in [.security/FINDINGS.md](.security/FINDINGS.md). Never suppress a new finding or broaden exceptions to make a gate pass.

Cursor Cloud setup now runs `bash .cursor/install-security.sh` (Python 3.10+), installing checksum-verified Gitleaks and pinned Semgrep and running the production audit and full code scan. Include `export PATH="$HOME/.local/bin:$PATH"` in every fresh cloud shell. The Semgrep version pin lives in `.cursor/install-semgrep.sh`. Registry access is required for installation/npm audit; local code rules run offline with metrics disabled. Keep `.security/`, `.semgrepignore`, `.cursor/`, `AGENTS.md`, `.githooks/` and `.gitleaks.toml` out of npm package contents.

## Complete repository privacy and language gates

The privacy gate also checks raw Git author/committer headers and commit messages. New commits require GitHub noreply; history permits only GitHub noreply and the exact public tool identities documented by metadata.py. Mailmap cannot conceal private identities. Commit-msg scans messages for secrets; pre-push runs metadata, full-history Gitleaks and full dependency/code checks. Use `python3 .security/merge-pr.py PR_NUMBER` from the reviewed PR checkout: it requires successful trusted GitHub Actions at that exact head, reruns full local gates, and merges with a matching-head condition. Private GitHub branch protection still depends on the account plan; this command is an enforced agent workflow, not a GitHub-side access restriction.

The code gate includes checksum-pinned ShellCheck at warning/error threshold for shell files, including extensionless wrappers, and Clang Static Analyzer for C/Objective-C helpers on macOS. Watchdog has a dedicated native-security CI job; Linux reports the platform handoff explicitly. No source language is silently claimed as analyzed by Semgrep. Add language-appropriate checks before adding a new runtime language. All scanners run locally and report locations/rule names without source snippets. Runtime downloads and separately installed language environments require their own dependency audit; npm audit of the parent manifest alone does not cover them.
