# Why the code is built this way

The code carries no comments (the comment ban in [TYPES-AND-LINT.md](TYPES-AND-LINT.md)). A reason that is not visible in the code lives here, or in the name of the test that guards it. Each entry names the file or function it explains. Read it before changing one of these on purpose.

## Reading the archive (`src`)

- **`src/db/open.ts` loads `node:sqlite` through Node's own `createRequire`.** A static `import { DatabaseSync } from "node:sqlite"` breaks under Vite and Vitest: `node:sqlite` is new enough that Vite's builtin module list does not know it, so it tries and fails to resolve it as a package. Going through `require` behaves the same under plain Node. ResMed-Data-MCP does the same.
- **`src/db/open.ts` sets a busy timeout.** The sync writer holds short transactions; waiting them out beats failing at once with `database is locked`. This process never writes.
- **Read only is a flag, not a URI.** Node 22's `node:sqlite` does not accept SQLite URI filenames (`file:...?mode=ro` fails with `unable to open database file`), so the guarantee is `readOnly: true` plus `PRAGMA query_only = ON`. The writable handle in `src/db/open.ts` is for tests that build a fixture file, and is never pointed at the live archive.
- **`src/mcp/queries.ts` reads the archive's row counts from `meta`.** The sync stamps the counts with its last commit, and it is the only writer, so they are exact. Counting `sgv` and `treatments` reads hundreds of MB when the page cache is cold, and `node:sqlite` blocks every other request meanwhile. `COUNT(*)` is only the fallback for an archive the sync has not stamped yet.
- **Treatments are read with a one day margin.** `treatments.created_at` is text, and its ISO format varies by uploader, so SQL narrows with a one day margin and the exact window is applied on the parsed time.
- **`insulin_effective` falls back to `insulin`** for archives the sync has not yet migrated. A combo's extended part is added only when its separate extended entry is absent (see the sync section below).
- **A sync with no run for an hour is stuck.** It runs every minute, which is why `sync_status` flags an hour.
- **`src/time.ts` caches the Chicago UTC offset per UTC hour.** Daylight saving changes happen on the hour, so this is exact. A timestamp string with no zone is read as UTC, which is Nightscout's convention, and never as the host's local time.
- **`src/mcp/profiles.ts` reads delivered basal from `Temp Basal` rows.** tconnectsync uploads every basal rate change (scheduled, Control-IQ and suspensions) as back to back `Temp Basal` rows, so the rows are clipped to the window. A spring forward gap has no instant for a schedule boundary inside it; the repeated fall back hour has two, and the earlier is meant by default (the profile tests name both).
- **`src/mcp/sql.ts` refuses meta keys and values that could carry a Nightscout URL, API secret or token.**
- **`src/keychainWrite.ts` sends the credential on stdin.** The `security` utility parses one stdin line, so credential bytes never enter the process arguments. Apple's interactive command buffer is 4096 bytes, so a longer value is rejected before any truncated write.
- **`src/mcp/httpAuth.ts`: an environment value that is set and non empty (infisical-run injects it) wins over the Keychain.** Comparison is constant time and never throws.
- **`src/mcp/server.ts` serves stateless Streamable HTTP.** A fresh `Server` and transport per request is what the SDK's stateless example requires, and the bearer token is checked on every request including `/health`. Port 0 keeps Node's ephemeral bind for tests only; product config never uses it.
- **Settings resolve in one order: an environment variable, then `config.json`, then the product default.** The default HTTP port is 8424 (ResMed 8420, Apple Tools HTTP 8421, Network Tools 8422, SimpleFIN 8423). It is only the preferred start: `serve` binds the next free port above it when it is taken.
- **`DIABETES_DATA_MCP_HOME` is a test and development override only.** The archive is written elsewhere by `com.diabetes-sqlite.sync`; this package never creates it.

## The sync (`sync/sync_from_nightscout.py`)

- **It was ported from the Grok box writer** so the schema and the daily and weekly math stay unchanged and box and Mini rows match.
- **Credentials fail closed.** Missing credentials exit 2 before the database is opened or created. Each value comes from its environment variable when set and non empty, else the Keychain, and is never printed or logged. The archive, lock and import files are owner only.
- **Nightscout 15.0.7 rejects JSON `find={...}`.** Treatments came back as JSON `null` (which the walker once read as "no more data") and entries as HTTP 500. Bracket parameters (`find[field][$lt]=`) work, and they also bypass the default treatments window of about 96 hours that a bare `count=` request uses. A backlog longer than that, such as tconnectsync catching up after a multi day stall, is only visible by paging with `find[created_at][$lt]`.
- **Paging stops at the newest stored reading, not the oldest.** Stopping at the minimum re-walked the whole archive, and with the broken `find` it died on page 2 every run. Treatments stop at `MAX(created_at)` for the same reason. A full backfill commits every page, so an interrupted one keeps what it wrote.
- **The treatment cursor is `$lte`, not `$lt`.** Treatments that share one `created_at` can straddle a page edge, and `$lt` would skip the ones that did not fit. Refetching the edge rows is a no op upsert.
- **`insulin_effective` counts insulin actually given.** A combo bolus in Care Portal shape stores only the immediate part in `insulin`; `enteredinsulin` is the total and `splitExt` percent of it is extended over `duration` minutes. When its own later extended row survived, that row carries the delivered units (fewer if the extension was cancelled), so the combo counts `insulin` only. When that row is absent (the current mapping drops it to avoid double counting in Nightscout's IOB), the combo counts `insulin` plus the requested extended units. A combo with no `insulin` at all is a request the pump never completed (cancelled, usually re-entered minutes later as a separate bolus), so it counts nothing. Every other row counts `insulin`. It is recomputed for all combos each run (a few hundred rows), and an extended row is matched to at most one combo. The sync tests name each case.
- **Profile mirror reads the newest documents on a routine run.** That is Nightscout's own default page size, so a new version or an in place edit of a recent one lands within a minute. The whole collection is re-read when the table is empty, once per local day, and in backfill and profiles modes, because only a full walk can see a document deleted upstream. A document deleted upstream is kept and flagged, not deleted, since the archive may be the only copy; tools ignore flagged rows. Unchanged documents (same content hash) are not rewritten.
- **A schedule always spans the whole day.** Like Nightscout's own lookup, the first segment also covers the time before its start, and a repeated start keeps the later entry.
- **Profile errors never undo the glucose and treatment sync committed before that step.** A profiles only run must not make the glucose archive look freshly synced, so it leaves that stamp alone. `sync_status` reads the stamps from `meta` instead of scanning both tables on every call.
- **Routine runs recompute only the newest days.** A full pass runs on an empty `daily_stats`, once per local day, and in stats, recompute and backfill modes. An archived week needs a full week of daily rows; only the week in progress may be partial.
- **After a full Nightscout walk the sync drops stored treatments Nightscout no longer has** (box era synthesized ids, or rows tconnectsync deleted and reposted under a new id), but only when the same event (`created_at` plus `eventType`) exists under an id Nightscout still has. Without that the old copy double counts insulin in the rollups. A row with no counterpart is kept, because that history exists nowhere else.
- **`sync/failure_diagnostics.py`:** before Python 3.10 a socket timeout raises `socket.timeout`, which is not a `TimeoutError`, so both are matched.

## The Tandem feed (`tconnectsync`)

- **The wrapper applies the combo mapping at import time** and edits nothing in site-packages, so `pip install` can never silently drop it. On any tconnectsync version other than the pinned 3.0.3 the mapping is not applied and a loud `WARNING` is logged; uploads continue as stock.
- **A true combo is one treatment.** Stock tconnectsync writes the immediate dose and, hours later, a separate insulin only "Extended Bolus" entry, so Nightscout cannot tell they belong together. `combo_bolus.py` merges them in the Care Portal shape and drops the later completion entry so insulin is not counted twice in IOB. If the request messages are missing it keeps the stock output (fail open to the two entry form; never lose insulin). It is pure Python 3.8+, duck typed on the event `NAME` attribute, so it is tested without tconnectsync installed.
- **The hourly window never uses `ignore_conn_errors`.** An unreachable Nightscout would read as "no pump row" and silently widen the window to the 28 day floor; the run fails instead. Window math is in UTC so a daylight saving change never shifts it an hour. A wider window re-sends nothing, because each processor still skips events at or before its own last upload; it only lets a delayed Tandem backlog be fetched. The date filter keeps the lookup outside Nightscout's default 96 hour window.
- **`enrich_combos.py` pads a day each way** because extended entries land later. It replaces a combo only when its old plain immediate dose document exists; otherwise the combo is already correct or was removed on purpose. The redundant completion document goes with it. It stubs `last_uploaded_entry` to re-emit everything in range.
- **`tconnectsync/install.sh` downloads with a stall guard.** A stalled GitHub path used to hang curl for about 650 seconds and then fail (curl 56). Each attempt now aborts after `STALL` seconds below 1 KB/s, and the next attempt resumes the partial file (`-C -`). The checksum is checked once a transfer completes; a complete file that does not match is deleted and fetched again, and a download that never matches still stops the install. A stale partial file larger than the real one makes curl exit 33 (range error) on every attempt, so it is deleted. `tests/download-retry.test.ts` runs the real `fetch()` against a fake curl.
- **The installer builds the environment at its final inactive path** because venv executables contain absolute paths, and switches with `rename(2)`, which replaces a symlink itself instead of following it as `mv` may. Previous runtimes stay for rollback. The managed Python runtime uses its own supported OpenSSL.

## Bundled Nightscout (`nightscout`)

- **The pinned runtime is prepared under a profile hash.** The hash selects an immutable prepared runtime, so an incomplete or failed build never replaces the current runtime and a future profile cannot reuse it. Downloads are verified against pinned sha256 values before unpacking, and source hashes are checked before any change is made. The MongoDB tarball unpacks into a directory named `mongodb-macos-aarch64--<version>`, which the installer renames.
- **`compat/apn-token.cjs`:** Nightscout only uses token authenticated APNs, so the certificate parser and its `node-forge` dependency are avoided while the notification and result contract is kept. Keys, device tokens, request payloads and headers are never propagated.
- **`compat/safe-console.cjs` and `sanitize-connect.mjs`:** the Dexcom connector logs whole credential configs, sessions and Axios request objects. Its verbose data dumps are disabled and only generic warning and error signals pass.
- **`compat/expand-pattern.cjs`** keeps the date range API with bounded depth, work and output allocation.
- **`prepare-runtime.mjs`:** jsdom delegates base64 to Node's globals, so mirroring its wrapper back onto those globals recurses; Node's browser compatible buffer functions are retained.
- **`diabetes-nightscout-server`:** secrets come from the environment first (infisical-run injects them) and then the Keychain; `config.env` never supplies one, and the environment copies are taken before `config.env` is read. The Dexcom Share bridge stays off unless `BRIDGE_ENABLE=1`, and only one Nightscout may poll Share at a time. Version 15 migrates `BRIDGE` to `connect`, so its settings namespace is enabled for explicit regions to be read; `US` and `EU` are legacy enums, not DNS hostnames. The wrapper waits up to 60 seconds for `com.diabetes-nightscout.mongod`. A missing secret exits 2.
- **`prove.sh` reads counts straight from Mongo** (Nightscout ships the driver) and sends the hashed API secret to curl on stdin, so no secret reaches a command line.

## LaunchAgents (`examples/install-launchagents.sh`)

- **An unchanged plist on a loaded job is left alone.** Every `bootstrap` makes launchd rescan all LaunchAgents with macOS Background Task Management, so a reinstall does not reload a job whose plist is the same. Jobs that run at load or stay alive restart in place (`launchctl kickstart -k`); a purely scheduled job, such as the hourly tconnectsync upload, picks up the new code on its next run and is not fired early. `tests/nightscout.test.ts` checks that a reinstall makes no bootout or bootstrap.
- **A plist runs its package script through `/bin/sh` or `node`, never the script itself.** Background Task Management keys an agent on its executable, so an npm reinstall that rewrites the script would otherwise post another "App Background Activity" notice (see Install and deploy in the README).
- **`bootout` returns before launchd has fully removed the job.** Bootstrapping too early fails with `5: Input/output error` and leaves the agent unloaded (this took mongod down once), so the installer waits for the old job to disappear and retries the bootstrap a few times.

## Gates and scripts (`.security`, `.githooks`, `scripts`)

- **The history scans read only the history being checked: the gated head, or each tip a push sends.** Never `--all` and never `rev-list --all`. A gate's worktree shares this repository's refs, so `--all` read other jobs' branches and scratch worktrees, and a debug commit authored on `example.invalid` failed the PR 544 push and the PR 533 gate in the Toolbox (Toolbox PR 554, Nov 12 2026). A delete sends no commits, so neither history scan runs on it; the file scan still does. `.security/test_standard.py` holds the probes.
- **Mocha is retried once, in the local gate only.** Under gate load an upstream request can fail with a localhost `ETIMEDOUT` that no timeout covers (PR 24, gate run 1, 5 minute load about 24, passed unchanged on the rerun; `TEST-CARB-004` sets its own 30 seconds). One retry absorbs that. A test that fails every time still fails the gate, and `scripts/mocha-retry-report.cjs` names any test that passed only on its retry on a gate warning line, because Mocha prints nothing for it and a real intermittent regression would pass unseen. Only a line that starts with the marker counts, and it never changes a result.
- **`scripts/nightscout-local-test.sh` refuses to start when port 1337 is taken** (the upstream tests bind it directly) rather than collide with anything live, and it aborts a stalled clone the same way the Tandem installer does (about 650 seconds before).
- **The commit hook scans staged bytes** so the additional gates match what is committed. Default image cloud agents skip `environment.json`, so the hook installs the tools to `~/.local/bin` itself. The Cursor installers fetch only checksum verified pinned releases (Cursor Cloud runs on Linux), keep the Semgrep pin through system pip because default cloud images omit `ensurepip`, set a committer identity because CI has none by default (no runner hostname is inherited), and export `PATH` for their own script only; the always applied rule sets it in new shells.
- **`.security/scan.py` rewrites the spelling of one TypeScript regular expression in its disposable scan copy** because Semgrep 1.180.0 misparses it as an HTML comment. The pattern and flags are identical and runtime files are never modified. It reads the index for tools, configuration, package metadata and candidate source, and scans explicit staged targets so an unstaged worktree is never scanned.
- **`.security/metadata.py`:** public tool attribution in old history is not a personal identity, but a new commit must always use the GitHub noreply address, tool generated commits included. It reads headers with `cat-file` because a mailmap cannot hide an identity.
