## Nightscout runtime repair

The runtime installer now prepares exact upstream v15.0.8 commit 92d0834219aa771b5837dbcbf1baeb839a200cf6 with a checked-in dependency manifest and integrity lock. SHA-256 checks reject changed upstream patch targets. A profile hash selects a separate runtime directory; failed preparation leaves the existing symlink intact. Production dependency audits run on the profile in full/staged gates and on the actual install before activation. Release publication requires the upstream runtime build/test job.

Updated vulnerable compatible dependencies, including Axios 0.34.0 for legacy cookie-jar clients and 1.20.0 for nightscout-connect. Replaced runtime braces with bounded brace-expansion 5.0.12; date/range behavior and malicious depth/size tests pass. Replaced the node-forge-backed APNs package with the token-only apns2 client through a small adapter; the upstream Loop path already uses token auth exclusively. Payloads, production/sandbox routing, masked errors and connection cleanup have offline regression tests. No real remote bolus, remote override or notification was sent for testing. D3's patched color dependency builds and passes upstream report tests.

The original repair cleared high/critical entries. The follow-up dependency profile below also clears lower-severity production findings. Development-only upstream tooling is removed by production pruning. No new audit or code exception was added. This review does not assert that every separately installed component or database binary is vulnerability-free.

The v15.0.8 Dexcom connector previously logged validated credential configuration and diagnostic session/request objects. Its exact installed source hashes are checked before a module-local console replacement suppresses verbose dumps and emits only generic warning/error signals. The actor also receives the filtered logger explicitly: XState invokes its own logger for actions.log and passes that option to child actors. The patch is idempotent and reapplied after production pruning; the application console remains available.

## Remaining dependency remediation

The follow-up Nightscout profile updates compatible dependency locks and pinned qs/Ajv, sanitize-html and style-loader, and substitutes the maintained Cypress request fork behind the legacy request module name. The complete production audit now requires zero advisories at any severity, in staged/full gates, upstream CI and runtime installation. Webpack and upstream browser/server tests verify compatibility. A hash-checked test-fixture change retains Node's native base64 functions rather than recursively mirroring jsdom wrappers into the globals they call; it does not alter production application behavior.

The Python installer replaces the obsolete system-Python environment with a checksum-pinned managed CPython 3.13.16 environment and hash-locked dependencies. All 37 distributions, including installer tooling, are checked through OSV; installation also verifies the actual installed graph and pip consistency before switching. The verified tconnectsync 3.0.3 wheel changes only its obsolete PyJWT requirement, retaining its application files and the existing combo-bolus hook. Offline tests exercise the real Tandem JWT parser with valid tokens and rejected invalid signature/issuer/expiry cases. Repeat-installation and failed-audit probes verify idempotence and preservation of the preceding environment. No real remote therapy command is used for testing. See tconnectsync/RUNTIME.md for rollback and scope.

Upstream Tandem authentication logs included decoded token claims at INFO and raw response details in exceptions. The wrapper filters that module's diagnostics to generic warning/error signals and catches unhandled sync exceptions without serializing response bodies or tracebacks; failure remains nonzero. Offline synthetic-secret probes verify masking. Other application diagnostics remain available.
